# Ядро для #4 Decode the Noise + #19 Wikipedia Through Time

**Рабочее имя проекта:** **Truth Rewind** (12 символов, лимит 30)
**Punchline (≤200):** *"Rewind any text to see who changed it, how, and whether it was a coordinated push: an explainable, measurable manipulation detector built on MariaDB time-travel tables."*

---

## 1. Идея в одном абзаце (как для ребёнка)

Представь машину времени для текста. Она хранит **каждую версию** статьи или поста, видит, **кто** и **когда** её менял, и замечает три вещи:
1. **Кто-то переписывает историю** (смысл статьи тихо поменялся).
2. **Целая толпа действует одинаково** (одинаковые тексты, правки в одно время = боты или координированная кампания).
3. **В тексте есть приёмы манипуляции** (запугивание, нагруженные слова, фейковый авторитет).

На всё она отвечает простыми словами и **показывает доказательства**: «вот версия до, вот после, вот 5 аккаунтов, которые сделали это за 10 минут».

- В **Wikipedia Through Time** это инструмент для читателей и редакторов: войны правок, переписывание истории Финляндии, «что писали в 2015».
- В **Decode the Noise** это детектор координированной пропаганды и тихих правок в новостях и соцсетях, задеплоенный на Hostinger.

## 2. Главная находка: MariaDB + Hostinger отлично дружат

- **MariaDB** обязательна для #19 и **отлично подходит** для #4: system-versioned tables = готовая «машина времени», а `VECTOR` = поиск похожих текстов (копипаста ботов).
- **Hostinger VPS** (обязателен для #4) — это обычный Linux с Docker → ставим туда MariaDB + бэкенд + фронт.
- **Один стек, один деплой → оба челленджа.** Разница только в источнике данных и экране.

## 3. Архитектура ядра (общие ~80%)

```
 ИСТОЧНИКИ (адаптеры)            ХРАНИЛИЩЕ: MariaDB                     АНАЛИЗ                            ВЫХОД
 ┌───────────────────────┐      ┌──────────────────────────────┐      ┌──────────────────────────┐     ┌────────────────────┐
 │ A) Wikipedia ревизии   │      │ documents  (WITH SYSTEM      │      │ 1. Diff & Timeline       │     │ Вердикт + причина  │
 │    (датасет MariaDB)   │ ──►  │            VERSIONING)       │ ──►  │ 2. Swarm Detector        │ ──► │ + доказательства   │
 │ B) Веб/новости/соцсети │      │ versions, actors, events     │      │ 3. Technique Classifier  │     │ Timeline-слайдер   │
 │    (Context.dev,       │      │ embeddings VECTOR(n)         │      │ 4. Source Trust          │     │ Граф «роя»         │
 │     Oxylabs, мониторы) │      │ + VECTOR INDEX               │      │ 5. RAG «спроси историю»  │     │ REST API + метрики │
 └───────────────────────┘      └──────────────────────────────┘      └──────────────────────────┘     └────────────────────┘
                                                                         ▲
                                                           Eval Harness: precision / FPR на размеченных данных
```

### Единая модель данных (одна для обоих)
| Таблица | Что хранит | Wikipedia | Decode the Noise |
|---|---|---|---|
| `documents` (system-versioned) | Текущий текст + вся история автоматически | Статья | Статья новости / страница / пост |
| `actors` | Кто действует | Редактор (аккаунт/IP) | Аккаунт соцсети / домен |
| `events` | Что и когда сделал | Правка (время, размер, комментарий, revert?) | Пост, репост, правка страницы |
| `chunks` + `VECTOR` | Кусочки текста с эмбеддингами | Абзацы версий | Тексты постов |
| `findings` | Что нашёл анализ | Война правок, смена тона | Рой, приём, тихая правка |

Ключевые запросы MariaDB:
- `SELECT ... FROM documents FOR SYSTEM_TIME AS OF '2015-01-01'` — «что было тогда».
- `FOR SYSTEM_TIME BETWEEN ... AND ...` — все версии для слайдера и диффа.
- `ORDER BY VEC_DISTANCE_COSINE(embedding, ?) LIMIT k` — похожие тексты (копипаста/RAG).

### Пять модулей анализа
| Модуль | Что делает (просто) | Как (технически) | Нужен в #19 | Нужен в #4 |
|---|---|---|---|---|
| **1. Diff & Timeline** | Показывает, что поменялось и когда | Дифф версий + LLM-резюме «смысл изменился так-то» | ✅ ядро | ✅ тихие правки новостей |
| **2. Swarm Detector** | Находит толпу, действующую слаженно | Синхронность по времени, похожесть текстов (вектор), цепочки откатов, граф акторов → кластеры | ✅ войны правок, sockpuppets | ✅ ядро «Spot the swarm» |
| **3. Technique Classifier** | Называет приём манипуляции и объясняет | Маленькая модель (Gemma) для скорости + LLM для объяснения; классы: нагруженная лексика, запугивание, вотэбаутизм, фейковый авторитет, нарушение нейтральности (NPOV) | ◐ смена тона/предвзятость | ✅ ядро «Name the technique» |
| **4. Source Trust** | Оценивает, можно ли верить источнику | Возраст домена, клон-контент, сеть ссылок, цитирования | ◐ качество ссылок в статье | ✅ «Trust the source» |
| **5. RAG** | Отвечает на вопросы с цитатами и датой версии | MariaDB vector search + LLM | ✅ RAG-трек | ◐ «спроси, почему это пропаганда» |

### Eval Harness (обязателен для #4, плюс для #19)
- На размеченных данных считаем **precision, recall, false positive rate** и показываем на отдельной странице.
- **Wikipedia даёт разметку бесплатно:** откаченные правки (reverts) ≈ «плохие», войны правок видны по цепочкам откатов.
- Для пропаганды и ботов: открытые датасеты (например, SemEval-2020 Task 11 по приёмам пропаганды, бот-датасеты вроде TwiBot / Cresci). Лицензии и доступность проверить сегодня ночью.

## 4. Две обёртки (оставшиеся ~20%)

### #19 Wikipedia Through Time → «History Rewind»
- **Экран:** выбираешь статью по истории Финляндии → ползунок по годам → подсветка изменений → бейджи «⚔️ война правок», «🧭 смена тона», «👥 возможная координация» → чат «что говорили в 2015 и что изменилось?» с ссылкой на версию.
- **Трек:** **ОБА (RAG + SVT)** → бонус за амбицию.
- **Для кого:** читатель (понять, насколько стабилен факт) и редактор (где нужен присмотр).
- **Критерии (по 20%):** MariaDB ✅ ядро, масштаб на 3 датасетах (показать small → large), польза, дизайн, оригинальность.
- **Мультиязычные эмбеддинги обязательны** (датасет финский).

### #4 Decode the Noise → «Narrative Rewind»
- **Экран:** вставляешь URL / тему / список аккаунтов → система собирает версии и посты (Context.dev мониторы + Oxylabs) → карточки: «🐝 рой из 14 аккаунтов, одинаковый текст за 9 минут», «🎭 приём: fear appeal — потому что…», «✏️ новость тихо переписана через 2 часа после публикации», «🔗 доверие к источнику: низкое — домену 12 дней» + страница метрик.
- **Обязательно:** живой публичный URL на **Hostinger VPS**.
- **Критерии:** 40% качество детекции (метрики + объяснение) ← модули 2–4 + Eval Harness; 25% деплой ← Hostinger; 20% оригинальность ← «машина времени» вместо одного поста; 15% демо.
- **Козырь:** Wikipedia можно показать как **второй источник** («тот же детектор ловит координированные правки в Википедии»): это демонстрирует общность метода.

## 8. Мини-словарик
- **SVT (system-versioned tables):** MariaDB сама сохраняет старую версию строки при каждом изменении. Как «история» в Google Docs, только для базы.
- **Вектор / эмбеддинг:** текст превращается в набор чисел; похожие по смыслу тексты дают близкие числа. Так ловим копипасту ботов, даже перефразированную.
- **Revert:** откат правки в Википедии. Если правку откатили, она, скорее всего, была плохой → бесплатная разметка.
- **Precision / FPR:** из того, что мы назвали «ботом», сколько реально боты / сколько честных людей мы зря обвинили.
